# 站内助手资料读取修复

问题源于检索策略：中文“总结论文库”无法命中英文论文标题，被误判成没有资料；原检索还固定取前十条、每条正文最多九百字符。本次按已登录身份和资料类型构建站内上下文，不更改身份验证或云端配置。

- 明确提到论文库、备忘录、待办、关注网站、行业前沿时按范围读取；未指定时使用当前页面。中文主题词支持短词组合，概览请求不会因关键词未命中就把资料库说成空。
- 可总结已保存的完整书目信息、摘要、分类、标签、笔记正文和待办状态。优先提供单条记录现有五万字符以内的完整正文；多条资料超出总预算时分批，单条书目与正文合计超出预算时明确标出节选。模型能看到是否节选，不能将节选称为全文。
- 不再静默限制前十条：按约六万四千字符上下文预算分批，回复显示本次读取数量、依据及剩余情况，并支持继续读取；指定某篇的追问使用上一批记录编号。
- 管理员可读取私人备忘录和待办。读者只获得公开网站、资讯与论文；伪造页面、编号、游标或历史身份不能越权。退出管理时中止请求、清空聊天及私人上下文。
- 站内总结优先于旧的外部链接整理上下文，避免“继续”或旧链接将论文库请求错误地送去网页分类。仍保留原有图片分析、链接整理、公开网页读取及显式保存流程。
- “总结论文库的资料”后附加的方法比较、输出格式或来源说明视为回答要求，不作为检索主题词，避免整库概览漏掉部分论文；明确写在资料范围前的主题仍可用于筛选。

## 可读范围与不能恢复的内容

历史论文导入仅保存元数据、摘要、文件名及文件哈希，原 PDF 二进制和导入时临时提取的正文没有作为附件留存。此次不会凭文件名读取用户电脑，也不会声称找回历史 PDF 全文。助手应先根据已保存摘要总结，并准确说明依据；需要逐页精读时仍需另外提供原文件或正文。

“站内资料”是网站数据库中当前身份有权读取的记录，不包括服务器上的任意文件、环境变量、API 密钥、SSH 私钥或系统命令。对话不直接修改业务记录；保存仍需管理员确认。

上下文、历史与模型回复均有长度限制，不能保证任意规模资料一次发送给任意模型。范围提示明确区分库内可读总数、匹配数量、本批数量和节选。检索时使用当前记录，若用户同时修改资料，后续批次以新状态为准。

未修改环境文件、依赖清单、锁文件、Next/TypeScript/Playwright/SSH 配置或部署模板；不迁移数据库，也不批量改写既有资料或 AI 设置。
